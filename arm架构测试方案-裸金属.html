ARM 架构测试方案

1. 测试目的

  • 评估 ARM 服务器与现有 x86 服务器在部署 StarRocks 集群时的性能差异，特别是在使用不同操作系统和存储配置下的表现。
  • 比较国产操作系统（如欧拉、麒麟、统信）与国际操作系统（如 Red Hat Enterprise 8.8）对数据库性能的影响。
  • 测试环境：ARM 服务器与现有非ARM环境对比，包括硬件（服务器、磁盘、存储）与操作系统（包括国产操作系统的对比）。

2. 测试环境

2.1 对照环境（x86 环境）

现有的非 ARM 集群，配置如下：

2.1.1 操作系统

  • 操作系统：Red Hat Enterprise Linux 8.8
  • 内核版本：4.18.0-477.10.1.el8_8.x86_64
  • 架构：x86_64

2.1.2 硬件配置

  • 处理器（CPU）：
    • 型号：Intel(R) Xeon(R) Gold 6530
    • 线程数：128 线程 32 Core(s) per socket * 2 Socket * 2 Thread(s) per core = 128
    • 架构：x86_64
  • 内存（Memory）：
    • 总内存容量：2TB
  • 存储配置：
    • 总磁盘容量：70T
    • 磁盘数量：10 个磁盘
    • 每台机器挂载数据：7T
    • 总数据量：7T
    • 当前磁盘使用情况：每台服务器磁盘已使用 710GB

注：x86 环境硬件信息补充： - CPU 核心数、主频：32 Core(s) per socket * 2 Socket * 2 Thread(s) per core = 128 线程 - 内存类型、频率：DDR4-3200MT/s - 磁盘类型、RAID 配置：RAID5 配置 - 网络配置：1GB 管理网卡 + 4×25GB 双端口网卡 - 存储阵列配置：2×32GB 双端口 FC HBA 卡

2.2 ARM 环境

2.2.1 服务器数量

  • 服务器数量：5 台 ARM 服务器

2.2.2 ARM 服务器硬件详细规格

每台 ARM 服务器配置如下：

  • 处理器（CPU）：
    • 配置 ≥ 4 颗鲲鹏 920 处理器
    • 单颗处理器核数 ≥ 48 核
    • 主频 ≥ 2.6GHz
    • 总核心数：≥ 192 核（4 × 48）
  • 内存（Memory）：
    • 配置 ≥ 32 条内存条
    • 单条容量 ≥ 64GB
    • 规格：DDR4-3200MT/s
    • 总内存容量：≥ 2TB（32 × 64GB）
  • 本地存储（硬盘）：
    • 配置 ≥ 2 × 960GB SSD 盘
    • 用途：系统盘和数据缓存
  • 网络配置：
    • 1 个四端口 1GB 以太网卡（管理网络）
    • ≥ 4 个 25GB 双端口网卡（含 25GB 模块）
    • 总网络带宽：≥ 200GB（4 × 2 × 25GB）
  • 存储连接（HBA 卡）：
    • 配置 ≥ 2 个双端口 32GB 光纤通道 HBA 卡（含 32GB 模块）
    • 用于连接 FC 存储阵列
  • RAID 配置：
    • 出厂预装 ≥ 4GB 缓存 RAID 卡
    • 用于本地 SSD 盘的 RAID 配置
  • 电源配置：
    • 配置 ≤ 2 个电源
    • 1+1 冗余配置
  • 外观规格：
    • 机架式服务器
    • 高度：2U

2.2.3 存储配置

  • 本地存储：每台服务器配置 ≥ 2 × 960GB SSD（系统盘）
  • FC 存储：每台服务器需要申请 1T FC 存储作为数据存储
    • 通过 32GB 光纤通道 HBA 卡连接
    • 用于数据的持久化和管理
    • 总存储容量：5 台服务器 × 1T = 5T FC 存储 - 需赵老师提供

操作系统测试策略

    • FusionOS - 需确认芯片适配的最新稳定版本

虚拟化平台
  • FusionCompute 虚拟化软件：

    • 支持虚拟机配置 RedHat、银河麒麟、龙蜥等主流操作系统

2.2.5 管理功能

  • 统一管理控制台：
    • 通过单一控制台管理全系列服务器产品
    • 支持跨数据中心设备集群管理

3. 测试场景设计

3.1 批量写入操作

在每个环境中模拟就诊表和账单明细表的大量数据插入操作，使用不同的操作系统进行测试。

3.2 复杂查询测试

执行多表联接和聚合查询，模拟现实中常见的医疗数据查询，比较不同操作系统下的执行性能。

3.3 增量更新场景

模拟有实时增量数据的场景，测试实时数据的插入、更新与查询性能。

3.4 离线数据分析

执行大规模的数据聚合与统计计算任务，评估不同操作系统下的计算资源消耗和执行时间。

3.5 高并发场景测试

  • 模拟高并发查询场景（1000+ 并发）
  • 测试连接池压力
  • 测试查询队列管理
  • 测试系统在高并发下的稳定性

3.6 长时间稳定性测试

  • 7×24 小时持续运行测试
  • 内存泄漏检测
  • 长时间运行后的性能衰减分析
  • 系统资源使用趋势分析

3.7 故障恢复测试

  • 节点故障恢复时间测试
  • 数据一致性验证
  • 自动故障转移能力测试
  • 存储故障场景模拟

3.8 混合负载测试

  • 同时执行写入、查询、分析任务
  • 测试不同负载下的资源竞争情况
  • 评估系统在混合负载下的性能表现

3.9 数据压缩与存储效率

  • 不同压缩算法的性能对比
  • 存储空间占用对比
  • 压缩对查询性能的影响

4. 性能测试指标

4.1 吞吐量（TPS）

测量不同操作系统下的吞吐量，在不同负载情况下的表现。

  • 测试不同并发数（100、200、500、1000）下的吞吐量，记录 TPS 值

4.2 响应时间（Latency）

记录查询操作的响应时间，分析不同操作系统下的查询延迟。

  • 测试复杂查询和批量插入的响应时间，比较不同操作系统对查询性能的影响

4.3 资源利用率

监控并记录每种操作系统下的 CPU 使用率、内存占用、磁盘 IO 和网络带宽。

4.4 SQL 执行时间

记录 SQL 查询执行的时间，特别是涉及多个表的复杂查询。

4.5 系统负载

监控系统负载，测试在不同并发和负载下的表现，特别是高并发下系统稳定性。

4.6 查询性能细分指标

  • 延迟分位数统计：
    • P50（中位数）延迟
    • P95 延迟
    • P99 延迟
    • 最大延迟
  • 查询吞吐量（QPS）：每秒查询数
  • 查询成功率：成功查询数 / 总查询数，记录失败率
  • 慢查询分析：超过阈值的查询统计和分析

4.7 写入性能细分指标

  • 批量写入速度：MB/s 或 行/s
  • 单条插入延迟：平均延迟、最大延迟
  • 写入失败率：写入失败次数统计
  • 数据一致性验证时间：写入后数据可见性延迟

4.8 资源利用率细分

  • CPU 利用率：
    • 用户态 CPU 使用率
    • 内核态 CPU 使用率
    • IO 等待时间占比
    • CPU 空闲率
  • 内存使用：
    • 堆内存使用情况
    • 非堆内存使用情况
    • 缓存命中率
    • 内存交换（Swap）使用情况
  • 磁盘 IO：
    • IOPS（每秒 IO 操作数）
    • 吞吐量（MB/s）
    • 平均 IO 延迟
    • IO 队列深度
    • 读写比例
  • 网络 IO：
    • 带宽使用率
    • 包丢失率
    • 网络延迟
    • 连接数统计

4.9 数据库特定指标

  • 查询计划执行时间：优化器性能分析
  • 数据扫描量：实际扫描数据量 vs 返回数据量
  • 缓存命中率：
    • 查询缓存命中率
    • 数据缓存命中率
    • 索引缓存命中率
  • 锁竞争：
    • 表锁等待时间
    • 行锁等待时间
    • 死锁发生次数

8. 测试报告模板

8.1 测试概述

测试目标

评估不同操作系统（Red Hat、欧拉、麒麟、统信）在 ARM 和 x86 环境下的 StarRocks 集群性能，特别是对吞吐量、响应时间和资源利用率的影响。

测试环境

  • 硬件环境：5 台 ARM 服务器与现有的 x86 集群环境对比
  • 操作系统：测试不同操作系统（Red Hat Enterprise 8.8、欧拉、麒麟、统信）对性能的影响
  • StarRocks 配置：
    • x86 环境：StarRocks 3.5.6，FE 3台，BE 5台
    • ARM 环境：StarRocks 3.5.6，FE/BE 节点数待确认（建议与 x86 一致）

8.2 测试指标

  • 吞吐量（TPS）：记录每种操作系统在不同并发下的吞吐量

  • 资源利用率：对比不同操作系统下的 CPU 使用率、内存占用、磁盘 IO 等资源的使用情况
  • SQL 执行时间：记录复杂查询的执行时间
