## 分项说明（证据链摘要）

| 指标 | 指标定义 | 计算公式要点 | 指标来源 |
|------|----------|--------------|----------|
| 实验医学标本数 | 条码/样本条数 | `COUNT(DISTINCT inspection_id)`，`inspection_date` 在统计月，`isdeleted='0'`，`CHECK_TIME IS NOT NULL`（运管单月版） | `lis_inspection_sample` + 收费关联 |
| 实验医学项目数 | 收费项工作量合计（报表展示为「项目数」） | `SUM(COALESCE(workload,0))` 按样本-收费项展开后汇总；**与《LIS提示词》中「项目数=医嘱数」表述需业务对齐**，实现侧为 **workload 累加** | `lis_inspection_sample_charge`、`lis_charge_item.workload` |
| 实验医学收入 | 检验收入（元） | 主院区：`SUM(SAMPLE_CHARGE)` 按 `GROUP_ID`；**合计**含天府时：`SUM(主院区总收入)+天府收费金额` | `lis_inspection_sample`；天府 `tianfu_data` CTE |

## 与主题设计文档口径对照（`LIS/LIS提示词`）

| 文档表述 | 实现侧（运管 SQL）说明 |
|----------|------------------------|
| 标本数 = 条码数 | 对应 `count(distinct inspection_id)` |
| 项目数 = 医嘱数 | 当前 Dolphin 整体 SQL 将 **工作量 sum(workload)** 输出为「项目数」列名；若考核口径必须是「医嘱条数」，需单独 COUNT 医嘱/申请维度并替换 |
| 收入（万元） | 贴源 SQL 多为 **元**；展示万元时需 `/10000` |

## 院区与合计（`运管科lis报表整体_单月_dolphinscheduler.sql`）

- **主院区**：`hid0101_orcl_lis_dbo` 系列表，按 `GROUP_ID` 映射亚专业组（免疫、生化、微生物、分子、临检与血液、急诊、温江、锦江等）。
- **天府院区**：`hid0117` 独立查询，`GROUP_ID` 白名单 + 排除部分 `charge_item_id` 的申请单。
- **合计行**：标本数/项目数/收入 = `final_summary` 汇总 + `tianfu_data`（天府）。
- **本部实际量**：排除映射为「天府院区」亚专业组后的汇总（脚本中 `WHERE 亚专业组 != '天府院区'` 段落）。

经营分析若只取 **「合计」一行** 的三个指标，应与脚本中 **合计** 行定义一致；若只取 **本部**，则用 **本部实际量** 行。

## 需业务/信息科确认项

1. **「实验医学项目数」** 最终口径：维持 **workload 合计**，还是改为 **医嘱数/收费项条数**（与 LIS 提示词完全一致）。  
2. **收入** 以 **SAMPLE_CHARGE（样本表）** 为准，还是以 **mdr_income / DC 收入主题** 为准（`lis常用sql统计` 提供医嘱去重关联收入方式）。  
3. 统计是否 **含温江/锦江/天府** 全院区，或仅 **主院区** —— 与报表「运管院区」筛选一致。
